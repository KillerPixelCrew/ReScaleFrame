# Windows 0.1.1 previews, 18 October 2026

Correction: the Project Wingman observer preview was withdrawn to draft. It
should not have been offered as a game release. Project Wingman remains
renderer research only; Drag'n Wash is the integration requested for the next
updated package. The build record below preserves what was prepared and checked.

Two separate prerelease downloads are built from the same committed source:

- **AC7:** dedicated DirectInput carrier, game plugin, Rust overlay and pinned
  DLSS/DLSS-G/Reflex, FidelityFX SR/FG and XeSS SR/FG/XeLL runtime payloads.
  FG defaults Off. Stable SR-only 0.1.0 assets remain available.
  No fresh AC7 gameplay acceptance is claimed.
- **Project Wingman:** XInput carrier, shared runtime and exact-build game
  plugin. This is a temporal-graph observer only. SR, FG, latency and VR
  processing remain unimplemented. No vendor-runtime payload is included.

Install guides: [AC7](ac7-development-install.md) and
[Project Wingman observer](wingman-observer-install.md). Each archive includes
its own file-hash/source-commit manifest and notices. Corresponding source and
SHA256SUMS accompany each download.

## Build correction and checks

The clean GitHub VS2022 build exposed C4127 in the AC7 pixel-enqueue template:
four ordinary conditions compared a template argument with fixed hook IDs.
Use `if constexpr` so the compiler selects the same specialization without
constant-condition warnings. No rendering algorithm or hook identity changes.

The next clean build exposed the same warning in the lifecycle template when
its quiesce check always returns OK. A result switch preserves every refusal
and successful transition without a constant Boolean condition.

After compilation succeeded, the clean runner failed the Wingman forwarding
fixture without a diagnostic. The fixture now prints carrier/system load
errors and marks only a missing system XInput 1.3 DLL as a dependency skip,
after checking carrier exports. Other load failures still fail. The actual
system forwarding check passes locally; a skipped CI check is not forwarding
acceptance and does not replace that local result.

Local Windows VS2026/MSVC Release verification with the pinned SDK headers
passes 44 native checks, with eight opt-in fixture skips, Rust formatting and
Clippy. All 59 Rust tests pass and the Release overlay builds. This is build
and fixture evidence, not gameplay or physical latency validation.

The AC7 packager now includes AMD's loader alongside its SR/FG libraries and
the MFG-Unlocker MIT notice alongside the existing SDK notices. The Wingman
packager uses an explicit three-DLL allowlist and portable observer config.
Both reject dirty source, verify ZIP integrity and per-file hashes, and emit
matching source archives and checksums. Vendor SDKs and binaries stay ignored.

Pinned runtime hashes match the AC7 packager's FidelityFX 2.3.0 and XeSS 3.0.2
requirements. Streamline is the official 2.14.1 x64 SDK retail payload. GPU
provider availability still follows the owning device and SDK.

Additional explicit RTX 5080 fixtures passed: `sr_pipeline` with the three
retail runtime directories, FSR3 -> XeSS FG -> FSR3 -> plain ownership with FG
disabled, and Reflex Off/On/Boost API submission (12 sleep calls, 72 lifecycle
markers, valid 64-bit frame IDs and SDK latency-report availability). These
checks do not establish enabled FG cadence, gameplay visuals or physical
latency. The SR fixture checks SDK evaluation and reinsertion; its result is
not a performance benchmark.
