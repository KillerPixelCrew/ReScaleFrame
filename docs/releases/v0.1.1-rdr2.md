# RDR2 0.1.1 build record, 29 October 2026

First RDR2 download. It packages the forced-DX12 ASI, shared runtime, RDR2 game plugin, Rust
overlay and the same pinned vendor runtimes as AC7 0.1.1: Streamline 2.14.1, FidelityFX SDK
2.3.0 and XeSS SDK 3.0.2. The target is Steam `RDR2.exe` 1.0.1491.50, build 13773296.
[Install guide](rdr2-install.md).

## Packaging

`tools/package-rdr2.py` assembles an explicit allowlist from the Release outputs and vendor
SDKs. It reuses the AC7 packager's helpers and Rust notice collection, rejects dirty source,
checks the FSR upscaler and XeSS SR hashes, verifies every archive entry against the manifest
and emits a corresponding-source archive and `SHA256SUMS.txt`. ScriptHookRDR2 and the ASI
loader are not redistributed. The packaged INI has portable defaults (DLSS SR, FG Off) and
diagnostics off; it holds no local paths.

## Checks

Windows VS2026/MSVC Release `eng/verify.ps1` passed: 104 discovered, 93 executed, 11 opt-in
skips, with Rust formatting and Clippy. Rust behaviour is unchanged, and the overlay DLL is
byte-identical to the one accepted in the 26 October RDR2 session (`14369273...03e43f`).

## What is and is not game-tested

Recorded RDR2 acceptance covers DLSS, FSR3, FSR4 INT8 and XeSS SR pixels, DLSS FG 2x/4x and
XeSS FG intervals, the shared overlay and all five runtime quality presets on an NVIDIA GPU in
normal SDR gameplay. See [the research](../research/rdr2-renderer.md) and
[handoff](../../games/rdr2/RESEARCH-HANDOFF.md).

That acceptance used the 26 October ASI and Runtime. The packaged ASI, Runtime and game plugin
were rebuilt after the 28 October shared-host migration (`d3bf0d6`), which moved RDR2 startup
and policy into the integration. Contract and fixture checks pass for them, but this exact
build has not run in RDR2. HDR, complete HUD modes, non-NVIDIA hardware, native graphics-menu
replacement and physical latency remain unverified.
