# Anomaly 0.1.2 build record, 12 November 2026

First Anomaly package, targeting the exact Anomaly 1.5.3 standard and AVX DX11 executables. The release source is
committed after the packager and this record are reviewed; the final manifest records that commit, rather than this
record predicting it. [Install guide](anomaly-install.md).

## Current-source shader packaging correction

Release 0.1.2 is already published; its historical shader payload is described
below. The uncommitted successor packager now ships only motion.rsfpatch, made
from committed RSF-authored rules/additions without a local game corpus. It does
not include original/r3, motion/r3, generated skin/foliage clones or shader caches
in either archive. Runtime obtains original source/includes from the game's own
engine filesystem and compiles verified variants locally. New provider/reload
behavior is built/fixture-tested, not newly game-accepted. This does not rewrite
the contents or acceptance status of the published 0.1.2 archives.

## Historical 0.1.2 packaging

The published release used the following packaging procedure (current-source behavior is corrected above):

```powershell
py -3 tools/package-anomaly.py --streamline-root D:/Coding/ReScaleFrame/.local/streamline/sdk
```

The output directory is `build/releases/anomaly`: `ReScaleFrame-0.1.2-Anomaly-Windows-x64.zip`,
`ReScaleFrame-0.1.2-Anomaly-source.zip` and `SHA256SUMS.txt`. The final run reports the listing, entry count and hashes.
`--dry-run` checks inputs and produces a private local motion deployment without emitting release archives; it allows
uncommitted development files. There is no dirty-source bypass for a distributable archive. Final packaging also checks
that HEAD and the clean source state did not change while it ran.

`rsf_proxy_thin_dinput8`, output `build/windows-x64/thin/bin/Release/dinput8.dll`, is the carrier. The inspected installed
54,784-byte copy matched this build output at SHA-256
`3a41d4e43661e42a80fc81e77ec2a2449917cc140e22ddf5c932e30b9ad08e1d`. The manifest records the actual packaged carrier
hash; later rebuilds need not have identical bytes. The Runtime and Anomaly adapter come from
`build/windows-x64/bin/Release`; the overlay is `target/release/rescaleframe_overlay.dll`.

The explicit allowlist includes those four binaries, portable INI, install guide, motion sources and notices, Streamline
2.14.1 retail SR/FG/Reflex DLLs, FidelityFX SDK 2.3.0 SR/FG DLLs and XeSS SDK 3.0.2 SR/FG/XeLL DLLs. Every one of the
14 vendor DLL hashes is pinned, including the same FSR upscaler and XeSS SR hashes used by AC7/RDR2. The manifest
hashes every payload entry; verification rejects extra/duplicate ZIP entries as well as CRC or hash failures. SHA256SUMS
covers both ZIPs. The corresponding-source ZIP contains the committed source and the generated motion HLSL inputs and
outputs, with their notices, not a machine-specific compiled shader cache.

The motion deployment is regenerated by `tools/anomaly_motion_deploy.py` from the pinned local 449-file r3 corpus
(`fdc260e0608f259d876c4ae0f11a6f2d8c03c001cf1fe82548794af1c6826a67`); it covers 73 allowlisted roots, including the
HS/DS chain. The expected namespace is `cd2c8238482f353bfe12eb9d2973e55f6f74f053f67e4b978b535aaff261b2c7` with the current
tools. The package includes original and transformed HLSL source bodies, with retained notices and GSC's X-Ray
noncommercial redistribution terms. They are not represented as wholly GPL-licensed RSF source. This release bundle is
an explicit expansion of the local deployment tool's historical "never shipped" scope; it must not silently turn into a
blanket license claim for all Anomaly game assets. No executable, texture, save, configuration from the player's game,
modding framework or machine cache is included.

The INI sets loader-relative module paths, Mode=Observe, Overlay=1, SRStage=5, SR=1, SRBackend=1 (adapter default DLSS),
Motion=1, FG=0 and FGBridge=1. FGBackend=7 is Auto. Capture and diagnostic switches are off, and no SDK/source/cache
path override is shipped. The adapter finds its vendor and motion folders relative to the INI. The new sharpening notice,
MinHook, GameSDK/MFG licenses, Rust dependency notices and all vendor terms accompany the binaries.

## Checks

The packager's unittest covers portable defaults and negative mutations, dirty-source refusal, vendor pin rejection and
archive membership/hash validation. Eight unit tests passed, and the reused Rust notice collector produced 116 notice
files. The development dry run passed against the actual local SDK/build inputs and regenerated the 905-file motion payload (73 roots), without a cache.
Its 937 allowlisted file inputs become 1,058 game-ZIP entries with the current generated notices, INI and manifest; the
final run reports the authoritative count. The dry run does not read or write the game installation. An actual dirty-tree
CLI run also refused before creating any release output. The coordinator's final clean-tree packaging run is required to produce publishable ZIPs and checksums; this record does not call a dirty dry run a release.

Native Anomaly development verification before packaging passed 94/94 selected anomaly/thin/motion tests and 44 binary
evidence checks for both executable profiles. Those are fixture/static results, not additional game runs. The coordinator
runs the full Release eng/verify.ps1 gate separately for the release commit. Final gate output and artifact hashes belong
in the release publishing record after that run; do not infer them from this development record.

## What is and is not game-tested

The coordinator/user reports acceptance on an RTX 4070 Laptop GPU for DLSS, FSR and XeSS SR, including Ultra
Performance; frame generation through the presentation bridge; the overlay and sharpening; borderless placement;
unjittered sun-cascade fitting; the jitter-aware sun depth margin; and the AVX executable profile. See the
[SR research](../research/anomaly-sr-seam.md), [FG research](../research/anomaly-fg.md) and
[profile evidence](../research/anomaly-avx-profile.md). This packaging task did not launch the game, and a fresh Release
rebuild is not automatically byte-identical to the accepted deployment.

AMD/Intel GPUs, HDR, exclusive fullscreen and scopes in depth are not tested. Provider/device support still controls
which FG choices are available. No physical latency measurement or broad readiness claim is added; code readiness flags
remain zero. This record describes the limited acceptance scope of the first download.
