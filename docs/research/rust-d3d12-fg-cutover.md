# Native D3D12 frame generation Rust cutover

The baseline is `2800090` on `rust/orchestrator-anomaly`. The question was whether one Rust owner could take over the D3D12 FG input and Present bookkeeping while preserving both the Runtime DLL and the embedded interfaces. The audit followed the actual leases from the engine callbacks through `native_sr_d3d12.cpp`, the DXGI facade in `d3d11_present_bridge.cpp`, and the selected generation provider. The Unity findings build on the [accepted native-copy correction](shared-fg-20261004.md). Provider resource requirements are recorded in [Frame generation contracts](vendor-fg-contracts.md).

| Boundary | Evidence and ownership |
| --- | --- |
| Normalized depth and motion | The existing `cs_5_0` normalization in `native_sr_d3d12.cpp` binds input depth and motion at `t1` and `t2` and writes R32_FLOAT and R16G16_FLOAT at `u1` and `u2`. It copies encoded device depth and converts adapter motion using `-render_extent * motion_to_uv`. The shader, SR descriptor heaps, exposure, sharpening and output reinsertion are outside the migrated owner. The FG copies start from non-pixel shader read and the provider receives unit motion scales for pixel vectors. |
| HUD-less and final colour | Unity's pre-UI event records on its current list and preserves the actual render-target descriptor. Godot matches submitted command-list pointers on its owning queue, with the submitted final scene covering the SR input copies. The generic render host matches registered recording, output surface and source before associating the window. Rust joins an exact session, source and view with the engine backbuffer index. Prepare receives the physical backbuffer in Present state. It receives HUD-less colour only from the matching output-sized capture when the UI mode requires it. |
| Submission and retirement | Unity's v7 header says its explicit list is executed on a worker and its returned fence value is set once the frame completes or the GPU is flushed. The inline HUD-less callback originally emitted an end event while the engine list was open. The window plugin event is configured to sync workers, flush command buffers and grant queue access. Unity now confirms the recorded source IDs there and uses its promised frame fence to include inline work in teardown. The Runtime holds copied textures until a real submission fence covers an untagged slot or the bridge joins the provider's retirement for a prepared slot. A failed or missing retirement pins resources through the generation; an unconfirmed source remains held until the producer quiesces and drains. |
| Prepare, Present and switch | The DXGI facade still owns allocator reuse, list closing/submission, the engine-to-provider queue join, physical Present, provider switching and backed-out plain fallback. Rust holds a slot through a failed prepare as well as a successful one because either call can leave GPU work in the list. A later same-generation queue join also covers earlier failed retirements. A drained generation transition may release unknown reads; allocations with uncertain recorded states are recreated. Detached pairs of final/HUD-less readbacks are written only after their matching physical queue fence. Shared frame-dump confirmation is restricted to the captured session, frame, view and resource generation. |
| CPU facts and status | The Rust input owner calls the existing shared CPU/pacing owner before taking its mutex, leaving older render and Present callbacks free to progress during pacing. The Runtime uses the shared marker calls at the same render and physical Present boundaries, checks session and provider generation, and preserves reset, missing facts, scene and HUD-less refusals. Vendor and latency status are sampled through the existing owners; vendor counters remain scoped to the active generation. |

The private C++ table supplies COM calls, SDK calls and the existing shared frame dump helper. Its public forwarding exports keep `native_fg_d3d12.h` intact. Direct Rust references to the full native host pulled DXGI and vendor symbols into the CPU-only link, so the full host registers its table and those binaries continue to use the same Rust archive without graphics dependencies.

## Verification

- VS2026 Debug built the Runtime DLL, both DirectInput carriers, Unity Mono game DLL, Unity package, Godot and Minecraft. Dumpbin matched all 14 FG12 export names on the Runtime and the five embedded binaries against the baseline Runtime.
- VS2026 Debug built `rsf_fg_present_bridge_test`, `rsf_unity_sr_d3d12_test`, `rsf_d3d12_observer_test`, `rsf_fg_leases_test`, `rsf_input_dump_d3d12` and `rsf_d3d11_present_bridge_test`.
- Nine focused CTest cases passed. The cases were `fg12_abi`, `fg12_abi_embedded`, `fg_status_snapshot`, `fg_leases_faults`, `native_cpu_reservation_contract`, `input_receipts_contract`, `xell_sleep_concurrency_contract`, `gpu_sr_policy` and `gpu_sr_policy_embedded`.
- `cargo fmt -p rsf-orchestrator --check`, Clippy with `--all-targets -- -D warnings` and all 27 `rsf-orchestrator` unit tests passed. The new retirement cases use copied generation state and a synthetic COM fence to exercise a missing join, pending completion and the device-removed sentinel.

The source audit establishes the handoff contracts and shader bindings. Live validation remains open for engine geometry, transparency, particles and volumetric motion coverage, provider switching, descriptor state under device removal, and moving-game image and latency results. The device fixtures were built only.
