# Runtime shader patch service in Rust

This source port starts at `8268cb9`. The Runtime shader patch service behind
`rsf_get_shader_patch_api` was C++ in `runtime/shader_patch/src`. Its decisions now live in
the [Rust owner](../../runtime/orchestrator/src/shader_patch.rs). The C++ side keeps the
unchanged public header, the `export.cpp` entry and the native leaves declared in the
private [platform table](../../runtime/shader_patch/src/platform.h). The Rust ABI file is
generated by `tools/generate-rust-bindings.py`. The service design and pack format are in
[runtime shader patching](runtime-shader-patching.md).

## Callers

| Entry | Callers at the baseline | Behavior kept |
| --- | --- | --- |
| `rsf_get_shader_patch_api` | Anomaly `runtime_shaders.cpp` by name from the loaded `ReScaleFrame.Runtime.dll`; the synthetic and corpus fixtures through `rsf_patch_query` | Short table `ARGUMENT`, other version `ABI`, then the full v1 table. One owner serves every client. |
| `open`, `hash`, `root_count`, `root`, `close` | Anomaly pack open and reload, manifest admission | Pack parsing, unique JSON keys and the 128-level limit, compiler identity, claims by original source hash, same-id overlap for reload, release on close. Root strings and hash stay borrowed until close. |
| `prepare` | Anomaly `RuntimeShaders::prepare` per engine compile | Engine source acquisition, source hash checks, ordered transforms, root allowlist and optional patched hash, original reproduction, cache key, verified cache hit, compile, reflection admission, refusal counters and reasons. Output bytes stay valid until the next prepare or close. |
| `attach_d3d11`, `create_d3d11` | Anomaly motion stage | Six MinHook detours on the device creation slots, one hook set per process, inventory of first bytecode per hash, and replacements created without being counted. |
| `constant_buffer`, `upload_constant`, `bind_constant` | Anomaly `motion_d3d11.cpp` | Size, usage, CPU access and slot checks and status codes. |
| `counters`, `dump` | Anomaly overlay status and Dump action | Same counters and `.dxbc`/`.asm` files. |

Only the Runtime DLL links the service. `export.cpp` is unchanged. Anomaly, AC7 and the other
adapters do not link it. The Rust code adds no exports to any module.

## Split

Rust owns the pack container, JSON admission, the session and claim registry, every source
operation, the root allowlist, the original proof, the cache key and files, reflection
policy, the DXBC rewrite and checksum, counters, the creation inventory, the hook set and
argument checks. SHA-256 and the compiler module identity use the same BCrypt and kernel32
calls as before, from Rust.

The leaves are `yyjson_read` with a document walk, `D3DCompile` with an `ID3DInclude` over
Rust-owned files, `D3DReflect` reporting facts, `D3DDisassemble`, the six device
`Create*Shader` calls, `CreateBuffer`, `GetDesc`, `Map`/`Unmap`, the six
`*SetConstantBuffers` calls and the MinHook calls. They return the foreign status and decide
nothing. The include callback resolves names case-insensitively with either separator, as
before. JSON integers keep yyjson's unsigned read of signed values.

The schema, pack bytes, cache file names and refusal codes are unchanged. Two development
entries replace C++ internals that the fixtures used directly: `rsf_patch_transform` returns
a pack's source tree and `rsf_patch_rewrite_dxbc` runs the synthetic rewrite. They are linked
into the Runtime but not exported.

## Behavior changes

- An insertion whose anchor offset lies inside the grown text but past the original text
  refused with `INTERNAL` because C++ threw `std::out_of_range`. It now refuses with
  `ANCHOR`. Stock shaders remain in use either way. The Rust test covers it.
- A cache file is published only after its write completes. Each writer uses a temporary name
  with its process ID and a counter. C++ renamed a shared `.tmp` even after a failed or
  partial write, and concurrent same-pack sessions could share that name. The final name and
  existing cache files are unchanged.
- Public records are admitted from their `struct_size` field before the rest is read, then
  by `abi_version`. A caller can pass a record that is only the size field.
- Allocation failure aborts instead of returning `INTERNAL`, as in the rest of the Rust core.

## Verification

All steps used the pinned Rust 1.94.1 toolchain and bindgen 0.72.1, with MSVC through the
Visual Studio 2026 generator. The baseline was exported from `8268cb9` and built in its own
tree with its own Cargo target directory.

- Rust passed 407 locked workspace tests, 261 of them in the orchestrator, plus formatting
  and workspace Clippy with warnings denied. The 12 new owner tests use fake leaves. They
  cover every pack truncation and table defect, JSON duplicate and NUL keys and the nesting
  limit, each source operation and its refusals, source hashes and payload collisions,
  reflection admission, the DXBC rewrite and MD5 constants, claims across reload and close,
  original proof, verified and root-specific cache hits, refusal counters and reasons,
  compile errors cut at the compiler's NUL, size-field-only records, cache publication and
  reuse, and the hook set, inventory and dump.
- Regenerating with bindgen changed no other binding. `shader_patch.h` is unchanged.
- `rsf_shader_patch_device_test.exe --cpu` passed through the real yyjson, D3DCompile and
  D3DReflect leaves. It covers the source operations, ABI refusals, claims, original proof,
  cache, refusals, every pack truncation, and a rewrite of FXC output whose stored checksum
  first had to match the first-party one.
- The coordinator's public DLL probe loaded the candidate Runtime and resolved
  `rsf_get_shader_patch_api` by name. It passed and wrote the same cache file name and DXBC
  hash as the C++ Runtime (`54bd647c….dxbc`, SHA-256 `04e0cc39…`). Its reopen probe reused
  the cache file the C++ Runtime wrote, and passed the short record checks.
- The Release PE comparison matched export names and ordinals for Runtime, AC7
  `dinput8.dll`, Loader and its `version.dll` alias, Minecraft and the Anomaly DLL. Only
  the Runtime's imports changed: the removed C++ no longer imports `_stricmp`, `isalnum`,
  `isalpha`, `strncpy_s` or the iostream helpers, and Rust std adds `DeleteFileW`,
  `NtReadFile` and ntdll's `RtlCaptureStackBackTrace` in place of kernel32's.
- The native Vulkan export, D3D11 presentation, overlay DLL and Anomaly plugin contracts
  passed. The `package_anomaly_test.py` pack contract passed.

The licensed 449-file corpus is not present locally, so corpus byte parity and the 73-root
engine compiler run were not repeated. The corpus fixture was rebuilt on the new entries.
The WARP part of the synthetic fixture, device and window fixtures, game runs and
`eng/verify.ps1` were not run. Logs are under
`.local/rust-1.94.1-verification/merged-worker-evidence/rust-shader-patch/`.

## Integrated Runtime and cold-cache Standard run

The combined shader patch and Anomaly configuration build at `74d4c48`
passed 413 pinned Rust tests, formatting, Clippy, eight MSVC Release
contracts, the shader patch CPU fixture and ten Anomaly package tests.
Runtime, AC7, Loader, thin carrier, version alias, Minecraft, Unity and
Godot export names and ordinals matched. Anomaly kept its three exports
and dynamic Runtime lookup. The merged public DLL probe reopened the
C++ cache unchanged and passed the short-record refusals.

The isolated Standard run used the merged Runtime, adapter and matching
pack with an empty motion shader cache. It opened 73 allowlisted roots
and compiled 79 replacement variants across the static, model, pixel,
foliage and tessellation families. The game resized to 1600×900, kept
DLSS-G active and reported 1,289 DLSS SR evaluations with zero refusals
in the last full sample. The engine shut down Direct3D and returned
code 0.

The new cache and logs were moved into the evidence directory and all
165 original cache files were restored and hash-checked. The staged
DLLs, pack, settings and script were also restored. Evidence is under
`.local/anomaly/staging/live-58fe95a-stage5/evidence/` in
`merged-rust-shader-cold-standard-74d4c48`. The AVX cold-cache run,
licensed corpus parity and shader WARP fixture remain open.
