# Immediate DLSS present pixels after dedicated capture fences

15 November 2026. Question: DLSS actual-present JSON establishes generated versus real ordinals, but bounded TotK runs can exit without normal renderer/provider drain, leaving the legacy pixel readbacks unwritten. This change adds a diagnostic-only immediate flush after the dedicated capture submission's known successful fence wait. No image, provider policy, SDK wait selection or native binary semaphore behavior is changed.

`runtime/orchestrator/src/native_fg_dlss_vulkan_capture.cpp`, `DlssPresentCapture::State::observe` already serializes callbacks with State::guard, records into a dedicated command buffer, submits using the real Present binary waits, and waits that submission's own fence before calling native Present with no waits. After that successful wait the current command's pending flag is cleared. `readbacks_completed` checks every command family for pending submissions, because an earlier callback may have timed out on another family. A later successful unrelated fence does not prove that earlier copy completed.

An additional retained-readback guard covers record/end/submit failures. FrameCaptureVk::record can retain partially allocated or recorded entries even when recording or submission fails. Pending-count deltas identify such entries. They are flagged unsubmitted, preventing later immediate flush and stopping further diagnostic recording on that dedicated capture owner. Ordinary native Present still follows its existing paths. Successful record, submit and wait can then call flush(false) only when all retained readbacks have completion proof. A failed wait returns exactly as before and keeps its pending flag. Retrying that family's own wait can restore proof; no global idle or provider/queue/session/PCL lock is acquired to manufacture completion.

The common FrameCaptureVk helper is unchanged. flush(true) is intentionally not used: it skips legacy entries without a core ticket. flush(false) errors are logged as completed-readback-flush diagnostics and do not replace the real Present result. Dedicated present JSON appends legacy_flush_attempted, legacy_flush_succeeded and nullable readback_completion_proof. The common per-image sidecar retains its historical owner-drained-context-retirement label; the dedicated sidecar now supplies the more precise own-fence proof. A successful boolean still requires actual .raw file inspection before claiming pixel/visual acceptance.

Capture-disabled behavior remains unchanged: no State is installed when capture is disabled, and unrequested frames retain the existing passthrough. No additional fences, waits, submissions, semaphores or borrowed-image ownership changes were introduced. The callback already owns its SDK queue; the new flush follows existing State->FrameCaptureVk lock order and never calls a provider or acquires a host queue lock.
