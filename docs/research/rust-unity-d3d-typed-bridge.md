# Unity Direct3D bridge cutover

This U03 source port starts from `8df04a40`. The two bridges already shared a
Rust packet store and scalar pass builder. Their C++ callbacks still owned
the Direct3D calls that recorded work and carried resources through GPU
completion. The port uses the existing `windows` 0.62.2 SDK bindings for
those calls and keeps Unity's SDK interfaces at the native boundary.

| Route | Source closure |
| --- | --- |
| D3D11 package, including Editor preview | `games/unity-mono/src/bridge_d3d11.rs` obtains the retained device and immediate context, uses the Runtime's linked native device and queue when available, and creates the same-adapter pair otherwise. It creates and retires command slots and shared fences through the existing `d3d11_state.rs` transaction. It checks source descriptions and resolves all surfaces before upload, waits across the shared fence, records transitions and work, hands back to D3D11, and publishes completion and copy-back proof separately through the Runtime ring. `d3d11_pass.h` is retired. |
| Direct D3D12, shared by Mono and the package | `games/unity-mono/src/bridge_d3d12.rs` owns the cached Unity frame fence, command allocators and lists, and the four resource references per GPU slot. It keeps the window flush, pre-UI capture on Unity's recording list, and reconstruction paths distinct. Reconstruction checks fence admission before releasing the old slot's references, reports a successful reset before host dispatch, and stores the new references before calling Unity's ExecuteCommandList. |
| Shared packet and receipt state | The native entry points acquire the same callback and packet leases. Rust supplies the COM retain and release callbacks for both Direct3D routes. D3D12 still uses the U02 receipt keyed by session, source frame and view. It checks capacity before inline recording, preserves receipts until the synchronized Unity window flush, and acknowledges a pending reconfiguration generation after the host callback. |
| Native boundary | `games/unity-mono/src/bridge.cpp` still registers Unity events, guards the Mono player lookup, and observes Win32 input. It supplies borrowed Unity COM identities and adapts Unity's recording state and ExecuteCommandList structures. `integrations/unity/native/bridge.cpp` retains renderer routing, Unity interface registration, the linked Runtime native queue query, and the package's existing COM output handoff. The managed packet and callback ABI, and the U04 Vulkan callbacks and retirement sequence, match the base. |

Bindgen 0.72.1 regenerated the private D3D12 Unity callback table and Runtime
shared-surface declarations. The existing shared packet and plugin bindings
also regenerated byte for byte. Rust 1.94.1 formatting, locked offline
workspace metadata and Git whitespace checks passed. Source comparisons
checked the U02 receipt bodies, U04 routing and retirement, and the
D3D11 and D3D12 ordering described above. Native builds, fixtures, and live
device behavior are unverified.
